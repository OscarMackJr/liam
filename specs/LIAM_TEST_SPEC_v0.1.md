# Liam — Windows Desktop Agent: Test Specification v0.1

Version: 0.1
Status: **Draft, POC scope** — companion to `LIAM_DESIGN_SPEC_v0.1.md`. Section references (§) point there unless stated.
Audience: the implementing LLM agent, reviewers of the POC evidence.

Principle carried from the nono work: **a test passes when Liam refuses, fails closed, or produces the required record.** A run that proceeds with a check missing is a failure even if nothing bad happened. Results are reported as measurements with their limits, never as claims.

---

## 1. Environments and Tags

Every test is tagged with exactly one environment. A test must not be marked verified from an environment with a different tag.

| Tag | Where | Token | Notes |
|---|---|---|---|
| `ci-elevated` | GitHub `windows-latest` | elevated | Hosted runners are elevated; ownership and mandatory-label behaviour differ from a standard user. Fine for logic, stubs, schema and build checks. Not sufficient for anything that depends on token type or file ACLs. |
| `dev-standard-user` | Developer workstation, standard (non-admin) account, nono fork installed | standard | Required for ACL, receipt-writability and real-nono tests. |
| `manual-hardware` | Managed workstation with CrowdStrike Falcon, live program endpoints | standard | End-to-end demo and detection seam. Coordinate with the endpoint team before running. |

## 2. Fixtures

### 2.1 Stubs (`stubs/`, feature `stubs`)

Small HTTP servers, started by the test harness on loopback, each with a scriptable response table.

| Stub | Behaviours it must support |
|---|---|
| `hometown-stub` | 200 with full context; 200 with `context_complete=false` and masked fields; 403 purpose refused; 500 |
| `gateway-stub` | 200 chat completion with and without a proposal block; 401 "no key presented"; 429; 500; 10 s delay (timeout); echoes received headers and metadata to a capture file |
| `olive-stub` | 202 `{proposal_id, status: queued}`; 200 `{status: rejected, reason}`; 400 schema error; catalog endpoint serving `catalog-0.4.json` |

Each stub writes every request (method, path, headers with `Authorization` presence flag, body) to a capture file the tests assert against.

### 2.2 Receipt fixtures (`stubs/receipts/`)

| Fixture | Content |
|---|---|
| `valid.json` | All required layers `active`, arm `appcontainer`, `egress.mode=proxy_only`, fresh timestamp (regenerated by `make-stub-receipt.ps1` at test time) |
| `degraded-layer.json` | One required layer `degraded` |
| `absent-layer.json` | One required layer missing from `layers[]` |
| `wrong-arm.json` | arm `low_il` |
| `stale.json` | `started_at` 10 minutes old |
| `wrong-profile.json` | `profile.name=other` |
| `old-profile-version.json` | `profile.version` below `profile_min_version` |
| `port-mismatch.json` | `egress.proxy_port` differs from `HTTPS_PROXY` |
| `signed-valid.json` / `signed-bad.json` | With `integrity.signature` valid / invalid against the test public key |

Writability is a property of the file ACL, not the content, so it is set by the harness (§3.1 TC-START-06).

### 2.3 Real nono (`dev-standard-user`, `manual-hardware`)

The nono fork at a pinned commit, with `profiles/liam.nono.toml` installed. The harness records the fork commit, the receipt version and the Windows build (`ver` plus UBR) in every result.

## 4. Reporting

Every result set is a table with these columns:

| Claim | TC | n of n | Tag | Windows build (ver + UBR) | Liam commit | nono commit | Limits / not measured | Status |

Status is one of `verified`, `refuted`, `not measured`. Rules:

- Three runs minimum for any `dev-standard-user` or `manual-hardware` case; CI cases run on every push.
- State what was not measured. A case tagged `manual-hardware` that was not run is `not measured`, never implied.
- No extrapolation across tags, builds, or nono arms.
- Sentinel and capture files are retained with the results so a reviewer can re-check them.

## 5. Exit Criteria for the POC

The POC is complete when:

1. Every `ci-elevated` TC is green on the pinned toolchain.
2. Every `dev-standard-user` TC is `verified`, 3 of 3.
3. TC-E2E-01, TC-E2E-03 and TC-E2E-04 are `verified` on at least one managed workstation, and TC-E2E-02 has carried one detection end to end.
4. Open items O1 (receipt fields) and O2 (ATE placement of `nono_session_id`) are either resolved or recorded as blocking, with the owner named.
5. The results table is published in the `liam` repository and summarised for the Fiskroad coordination repository.

Not required for POC exit, and must not be claimed: fleet distribution, log shipping, any execution of actions, CrowdStrike coexistence beyond what the nono fork's own soak establishes.
