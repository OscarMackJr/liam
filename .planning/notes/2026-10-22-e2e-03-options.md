# E2E-03 / TC-E2E-07 redesign options (amendment v0.4.2, O-E)

Date: 2026-10-22
For: the Liam owner (decision) and nono-12 (facts marked **ask nono**)
Status: proposal. Nothing changed in code, specs or requirements.

## The problem

E2E-03 (REQ-LIAM-17, TC-E2E-07, Phase 5) says:

> A deliberate gateway attempt is blocked by nono and detected with the gateway host as
> `destination`, and the run still completes through hometown.

That was written for v0.4.1 D14: Liam sent everything as CONNECT through nono-proxy, so a
deliberate CONNECT to the gateway FQDN would hit nono's host allowlist and nono would see the
host. Under v0.4.2 (ratified 2026-10-22), Liam has no forward proxy. Its only client has
`no_proxy()` and a deny-all resolver, and it only reaches `http://127.0.0.1:<proxy_port>/svc/<id>`.
The current stub gateway attempt (`LIAM_STUB_GATEWAY_ATTEMPT=1`, `src/stubs.rs`) fails inside
Liam at the resolver. Nothing leaves the process, so nono has nothing to block or detect.

## What nono does today (read-only check of `~/Nono` at `25220da1`, 126.1 plans 01-04)

- **No `endpoint-detection/0.1` emitter.** No hits in `crates/`. `NONO_v0.4` lists it as carried
  from v0.3 and still outstanding. Any option that requires this exact schema needs new nono work.
- **nono-proxy has its own audit log** (`NetworkAuditEvent`, `crates/nono-proxy/src/audit.rs`),
  with modes `connect` / `reverse` / `external` and a denial category. CONNECT denials and reverse
  endpoint-policy denials (`log_denied`, with `route_id = service`) are recorded.
- **An unknown reverse route is not audited.** `reverse.rs` returns `ProxyError::UnknownService`
  with no `log_denied` call. So `GET /svc/gateway` is refused but leaves no audit event.
- **No WFP drop-event logging** (no `FWPM_NET_EVENT` use). WFP blocks a direct socket, but
  nono does not record it.
- Every agent profile declares the gateway FQDN (for the popeye exchange), but the child gets no
  gateway URL unless `gateway` is in `inject_on` (amendment O-D).

## Options

### A. Deliberate request to the gateway route on nono-proxy (recommended)

The test build sends one `GET http://127.0.0.1:<proxy_port>/svc/gateway`. It uses the same single
client and the port from the validated hometown URL, so there's no host name, no DNS and no
token. nono-proxy refuses it because gateway isn't in `inject_on`, and records a denied
reverse-mode event with `route_id = "gateway"`. The run then completes through hometown.

- Liam change: about 5 lines in `stubs::gateway_attempt` (still feature `stubs`, never in release).
  TC-NET-03 stays clean: the route is built from the service id, and there's no gateway host
  literal in non-stub source.
- nono change (**ask nono**): audit the `UnknownService` miss as a denial, with a content-free
  category, and get that event out to an observable sink (session audit or a detection record).
- Requirement change: `destination` becomes the **gateway service id** on the loopback route,
  not the gateway host. The meaning holds: nono enforced "Liam can't reach the gateway" and
  recorded the attempt.
- Risk: it tests a refusal Liam's real code path could never trigger. That's true of every
  deliberate-attempt test, including the original one.

### B. Deliberate CONNECT through nono-proxy (closest to the original wording)

The test build sends `CONNECT <gateway FQDN>:443` to `127.0.0.1:<proxy_port>`, and nono's
host-normalized allowlist refuses it with the host recorded.

- Blocker: real sessions require `nono:<session token>@` proxy auth. Without it, nono-proxy
  most likely rejects at auth (407) before the host decision, so the event records an auth
  failure, not a gateway host (**ask nono**: is an unauthenticated CONNECT host-checked and
  audited?). Getting the token means reading `HTTPS_PROXY`, which amendment O-A forbids. The
  test would also need a second, proxied client, which TC-NET-03 forbids. Even feature-gated,
  this undoes the point of v0.4.2.
- Not recommended.

### C. Direct socket from a separate probe, blocked by WFP

A separate test tool (not Liam) inside the same nono session connects to the gateway's IP.
WFP drops it.

- nono change: WFP net-event logging mapped to a detection record. That's larger than A.
- It also moves the subject of the test from Liam to a helper process, so REQ-LIAM-17 is no
  longer about Liam.
- Not recommended for the POC.

### D. Drop "detected", keep "cannot reach"

Restate REQ-LIAM-17 as a property, without a nono detection:

- Liam source has no gateway reference (TC-NET-03).
- The deny-all resolver stops any host-name request (TC-NET-04: resolver count 1, zero bytes at the trap).
- A real session shows zero DNS from Liam's PID (TC-NET-08).
- The agent record shows `injected_on = {hometown, olive}` and `direct_gateway = false`, and
  no gateway URL is given to the child (O-D).

- No nono change. The weaker claim: "blocked by nono and detected" becomes "unreachable by
  construction and by nono configuration". The program loses its one endpoint-side
  detection example.
- Good fallback if nono declines the A work for the POC.

## nono answers (nono-12, 2026-10-22, code read at `9a0024b2`; facts, not commitments)

1. **UnknownService is not audited, and 126.1 doesn't plan to audit it.** No denial category
   exists for a route miss. Option A would need a nono follow-up:
   - a new category (e.g. `UnknownRoute`) and a `log_denied` call at `reverse.rs:121`;
   - a bounded or sanitized `route_id`, since the missed segment is attacker-controlled path text;
   - a fix to `parse_session_service`, which today records an unregistered `/svc/gateway` as
     service `svc`, not `gateway`.
2. **Where audit events go.** They are held in memory, drained at session finalize
   (`nono-cli/src/rollback_runtime.rs:727-737`) and written to `SessionMetadata.network_events`
   on disk. They are not in the `SessionEndRecord` or the receipt. It is unverified whether the
   Windows agent-session `nono run` path reaches finalize; that depends on 126.1 plan 10.
3. **`endpoint-detection/0.1` is not planned.** `NetworkAuditEvent` is the only detection
   artifact nono has.
4. **Unauthenticated CONNECT depends on the target host.**
   - Session-injected FQDN: refused as `SessionInjectedHostBypass` before auth.
   - Any other host: auth is checked first. In `strict_auth`, missing auth gets a 407 and an
     `AuthenticationFailed` event. In the default non-strict mode (sandboxed run/shell/wrap),
     missing auth is non-fatal and the request reaches the host filter, so a denied host is
     audited as `HostDenied`.

### What changes

- **A costs more than estimated.** It needs a three-part nono follow-up that 126.1 doesn't
  plan, and its destination would still be a route id, not the host.
- **B is viable without the token** if agent sessions use non-strict auth.
  - The test sends `CONNECT <gateway FQDN>:443` with no `Proxy-Authorization` to
    `127.0.0.1:<proxy_port>`. It never reads `HTTPS_PROXY` and resolves nothing, since nono
    does the host check.
  - nono denies the host and records `HostDenied` with the gateway host. That matches the
    original E2E-03 wording, with no nono code change.
  - The CONNECT would be a few lines of raw socket code under feature `stubs`, which TC-NET-03
    already excludes. Liam's single real client is unchanged, and release builds carry none of it.
  - Two open facts decide B:
    - **B-1.** Do Windows agent sessions run with non-strict auth? If they use `strict_auth`,
      the request ends at 407 / `AuthenticationFailed` and never reaches the host check.
    - **B-2.** Is the gateway FQDN on the Liam session's CONNECT allowlist? O-D says every agent
      profile declares it for the popeye exchange URL. If declaring it also allows it, the
      CONNECT would be permitted, not denied.
- **All options share one open item:** whether the Windows `nono run` agent path reaches
  finalize, so that `network_events` lands on disk. 126.1 verification answers it.

### B-1 / B-2 answers (nono-12, 2026-10-22, `9a0024b2` + 126.1 plan 10 text; recheck after plan 10 lands)

- **B-1, auth mode: non-strict.**
  - `ProxyConfig::default` sets `strict_connect_auth = false` (`nono-proxy/src/config.rs:159`).
    Only `nono proxy` sets it to true; `nono run` doesn't.
  - Without strict mode, missing auth isn't fatal and the request goes on to the host filter.
  - 126.1 doesn't change this, but nono may choose strict mode for agent sessions later as a
    hardening step. **Non-strict is not a contract.** If nono switches, B breaks and falls back
    to D.
- **B-2, allowlist: nono adds no gateway entry.**
  - The child's CONNECT allowlist is exactly the profile's own network allowlist.
  - The popeye exchange is done by the supervisor before the proxy starts, not through the
    child's proxy.
  - `validate_inject_allowlist` refuses launch if an `inject_on` service FQDN is **not** on the
    allowlist, and it skips gateway.
- **Conditions for `HostDenied`:**
  - (a) The profile's network allowlist must be **non-empty**, because an empty allowlist means
    allow-all.
  - (b) `gateway` must stay **out of `inject_on`**, or the CONNECT is refused as
    `SessionInjectedHostBypass` instead. nono-12 corrected this one: a profile can list gateway in
    `inject_on`. Liam's lists only `["hometown", "olive"]`.
  - (c) The audit host is the CONNECT authority as sent. The persistence path (Q2) is
    unverified for agent sessions.

### Profile gap this exposes (affects Phase 2, not only E2E-03)

`profiles/liam.nono.toml` has **no network section**. Under 126.1 that means:

- **Launch refusal.** `validate_inject_allowlist` would refuse to launch, because the hometown and
  olive FQDNs are not on the allowlist. Phase 2 can't run until the profile declares them.
- **Gateway reachable.** Even if launch were allowed, an empty allowlist is allow-all, so D12
  ("gateway not allowed") would not hold.

The fix is a profile change for nono-owner review: an explicit allowlist with exactly the
hometown and olive API FQDNs, no gateway, and no group or wildcard that covers it (design §150).
This is draft-profile work that belongs in Phase 2 (re-run of gate 1 / 02-04), under change
control; it is not made here.

## Recommendation

Revised after the nono answers: **B (raw CONNECT under feature `stubs`, no token)** if B-1 and
B-2 hold (non-strict auth, gateway not allowlisted for the Liam session). Otherwise **D**.
**A** only if the owner wants to fund its nono follow-up.

The original recommendation, kept for the record, was **A**, with **D** as the fallback. A keeps a real nono enforcement-and-record step, needs only a
small, content-free nono change and keeps every v0.4.2 rule. If nono-12 says the
`UnknownService` audit or its export won't land before Phase 5, take D and record the lost
detection as a known gap.

## Questions for nono-12

1. Will 126.1 (or a follow-up) audit `UnknownService` reverse-route misses as denials? Which
   category, and is the route id recorded?
2. Where does a session's network audit end up (sink, file, session end record)? Can Liam's
   Phase 5 read it without breaking "Liam reads only the receipt and agent record"? (The
   operator or test harness reads it, not Liam.)
3. Is `endpoint-detection/0.1` emission planned at all? If not, Phase 5 reads nono's
   `NetworkAuditEvent` instead.
4. For B only: is an unauthenticated CONNECT host-checked and audited, or refused at auth first?
