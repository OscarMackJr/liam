## Pattern Assignments

### `src/config.rs` - new pure service-URL validator

**Analog:** `validated_proxy` (config.rs 51-89) plus its unit tests (144-179).

Current shape to replace (lines 51-89): pure fn, `&'static str` reason, exact-form check by `strip_prefix` + round-trip `format!` equality:
```rust
pub fn validated_proxy(https_proxy: &str, http_proxy: &str, no_proxy: &str)
    -> Result<ValidatedProxy, &'static str> {
    ...
    let port = https_proxy.strip_prefix("http://127.0.0.1:").ok_or("env:proxy_not_loopback")?
        .parse().map_err(|_| "env:proxy_not_loopback")?;
    if port == 0 || https_proxy != format!("http://127.0.0.1:{port}") { return Err("env:proxy_not_loopback"); }
    Ok(ValidatedProxy { url: https_proxy.to_owned(), port })
}
```
Copy: signature style (inputs as args, `Result<_, &'static str>`, no env/fs). New suggested signature (D-07): `validated_service_url(value: &str, route: &str /* "/svc/hometown" */, proxy_port: u16) -> Result<String /* validated base */, &'static str>`, called once per variable, or a wrapper taking both. Empty/absent -> `env:service_url_missing` (main passes `env::var(..).unwrap_or_default()`, same idiom as lines 144-145).

Check order to implement (D-05): missing -> not_loopback (scheme/host/userinfo/query/fragment) -> port -> route. Keep the round-trip equality idiom to reject `0`, leading zeros, `+80`, trailing `/`, `//svc/hometown`, `/svc/hometown/x`, `%2e` tricks.

**Strict-parse crate (answer to "which crate"):** `url` 2.5.8 is vendored (`vendor/url`, with `idna`, `idna_adapter`) but is NOT a direct dependency (no `url` in Cargo.toml). `reqwest::Url` re-exports it; use `reqwest::Url::parse(value)` - parsing never resolves names (hosts are parsed only; `Host::Domain` vs `Host::Ipv4`). No new dependency, no vendor change. Caveat: `Url` normalizes (lowercases scheme/host, strips default port 80, accepts `http://127.1`, `http://2130706433`, `http://0x7f.0.0.1` as Ipv4 `127.0.0.1`, drops empty fragment `#`/query `?`). Therefore either (a) parse only for component checks and ALSO require `url.as_str() == value` (round-trip, rejects normalized forms and `...?`/`...#` empties), or (b) do the manual `strip_prefix("http://127.0.0.1:")` parse as in `validated_proxy` and skip the crate. Recommended: manual prefix parse for scheme/host (guarantees the literal form), `reqwest::Url` optional only for query/fragment/userinfo detection. Note `http://127.0.0.1:80/...` round-trips differently under `Url` (port elided), so port must be taken manually. Unit tests should include the IP-obfuscation forms above.

**Struct changes (lines 29-40):** delete `base_url` from `ServiceConfig` and `OliveConfig`; keep `timeout_seconds`, `catalog_path`, `catalog_version`. `toml` deserialization has no `deny_unknown_fields`, so an old `liam.toml` with `base_url` would parse silently; the planner may want a test that `liam.toml` has no `base_url`.

**Unit-test pattern to copy** (config.rs 144-179): `accepts_only_...` happy path with `assert_eq!` on parsed values, and `rejects_...` iterating a `for value in [..]` array asserting the exact `Err("env:...")` string. Replace `use super::{resolve_runs_dir, sha256_hex, validated_proxy}` (line 111).

### `src/stubs.rs` - capture proxy -> `/svc/` listener

**What exists today (forward proxy, absolute-form):** two families.
1. `CaptureProxy` (lines 26-185; `forward_once_to`, `forward_once`, `forward_two`, `forward_two_to`): a tiny_http server on `127.0.0.1:0` that receives each request, records `has_authorization`/`method`/`request_count` in `ProxyCapture`, then forwards the body with `reqwest::blocking::Client::new().post(target)` where `target` = fixed `target_base + fixed path` (it IGNORES the incoming path and host; it never inspects CONNECT) and injects `Authorization: Bearer proxy-sentinel`. Used by `process_contract.rs`, `proxy_contract.rs`.
2. `TestProxy` (lines 752-970) + `handle_proxy_request` (790-895): routes by authority. `split_target` (780-788) handles absolute-form (`http://host:port/path`) and falls back to the `Host` header; routing compares `authority == shared.hometown || shared.olive` (from `authority_of(base)`); `refuse` list contains `gateway.invalid` (trap/refuse counters in `ProxyStats`); injects the sentinel only when `inject`; `ProxyStats { hometown_hits, olive_hits, gateway_attempts, refused_count, inbound_authorization_count }` is asserted by tc_key_01 and others. Neither implementation records CONNECT: tiny_http would answer a CONNECT as a normal request with `request.url()` = `host:port` and no scheme, which `split_target` would treat as an origin-form path; there is no explicit CONNECT bookkeeping.

**Why it must change:** with no `Proxy::all`, reqwest sends origin-form requests (`POST /svc/hometown/v1/agent/answer`, `Host: 127.0.0.1:<port>`) straight to the listener. `split_target` falls to the Host-header branch and returns authority `127.0.0.1:<port>` with path `/svc/hometown/...`; that matches neither upstream authority, so `TestProxy` would 502 ("unroutable authority"). `CaptureProxy` would work but forwards to a fixed path, ignoring route.

**Pattern to copy for the new listener (D-15):** keep `TestProxy::start`'s spawn/recv_timeout/handler-thread/`Drop`-joins loop (897-970) and `handle_proxy_request` forwarding skeleton (848-895). Replace authority routing with path-prefix routing:
```rust
// inside handle_proxy_request, replace authority/host logic
let path = request.url();           // origin-form
if let Some(rest) = path.strip_prefix("/svc/hometown") { target = format!("{hometown_base}{rest}"); stats.hometown_hits += 1; }
else if let Some(rest) = path.strip_prefix("/svc/olive") { target = format!("{olive_base}{rest}"); stats.olive_hits += 1; }
else { errors.push("unroutable path"); respond 502; return }
// CONNECT: if request.method().as_str() == "CONNECT" -> stats.connect_attempts += 1; respond 403/405
```
Require `rest` to be empty or start with `/` (so `/svc/hometownX` is rejected). Add to `ProxyStats`: `connect_attempts: usize`, and capture `paths: Vec<String>` (or a `Vec<CapturedRequest>` reusing the existing `CapturedRequest { method, path, header_names, authorization_present, body }` struct at 613-620) so TC-NET-09 can assert every request begins `/svc/hometown` or `/svc/olive` and `authorization_present == false`. Keep sentinel injection on forwarded hop (`builder.header("Authorization", "Bearer proxy-sentinel")`) so stub-side `authorization_present` assertions (tc_key_01 lines 130-134) still hold. `inbound_authorization_count` stays.

Gateway trap (`GATEWAY_HOST`, `GatewayTrap`, `gateway_attempt` 1042-1047, `with_gateway_trap`, main.rs 200-207): `gateway_attempt` does `client.get("http://gateway.invalid/")` through the proxy-forced client. With no forward proxy that URL goes to the deny-all resolver and fails closed (resolver_calls would be 1, not 0!). The planner must decide: rewrite as "Liam never requests a non-`/svc/` path" (path other than the two prefixes -> `gateway_attempts += 1`, refused), or retire the negative control. Tests `gateway_attempt_is_refused_and_trap_untouched`, `gateway_negative_control_fires_the_trap` (1171-1197), and `tests/action_contract.rs` 414-470 (TC-NET-04) depend on this. Also `scripted_tests::proxied` (1061-1068) and `proxy_routes_injects_and_counts` (1131-1158) build a client with `Proxy::all` - fine inside `#[cfg(test)]` stubs (excluded from the static scan, which does `files.retain(|p| *p != stubs)`; static_contract.rs 194), but they must be rewritten to origin-form `/svc/...` requests.

**Port/record pairing:** `StubRecordPair::for_proxy(proxy_port)` (195-219) writes `"proxy_port": proxy_port` into the agent record; tests pass `proxy.port()`. Keep: the single listener's port IS `proxy_port`. Process tests must now pass env `NONO_SERVICE_HOMETOWN_URL=http://127.0.0.1:<port>/svc/hometown` and `NONO_SERVICE_OLIVE_URL=http://127.0.0.1:<port>/svc/olive` (add helper e.g. `proxy.hometown_url()` / `olive_url()`). Both upstream stubs still bind their own random ports (`HometownStub`, `OliveStub`, `ScriptedStub`, base_url fields), forwarded to by the listener.

## Open points for the planner
