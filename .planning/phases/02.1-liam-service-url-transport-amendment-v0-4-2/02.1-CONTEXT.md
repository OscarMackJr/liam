# Phase 02.1: Liam service-URL transport (amendment v0.4.2) - Context

**Gathered:** 2026-10-22
**Status:** Ready for planning
**Source:** PRD Express Path (`specs/LIAM_AMENDMENT_v0.4.2_service-url-transport.md`)

<domain>
## Phase Boundary

Liam stops using a forward proxy (CONNECT via `HTTPS_PROXY`) and instead calls nono-proxy's per-service loopback reverse-proxy routes, given in `NONO_SERVICE_HOMETOWN_URL` and `NONO_SERVICE_OLIVE_URL`, validated against the agent-session record. Local only (stubs, CI tags `ci-elevated` / unit). No real nono session in this phase; nono Phase 126.1 builds the nono side.

</domain>

<decisions>
## Implementation Decisions

### Gate (LOCKED)
- **D-01** Execution of any `src/`, `liam.toml`, `tests/` or `contracts/` change is gated on the amendment's Ratification Record being filled (Decision, Date, Ratified by) together with the `NONO_v0.4.2` §2–§3 revision. The first plan's first task is a blocking `checkpoint:decision` for the user (the ratifier). If not ratified, the phase stops with no code change.
- **D-02** No change to `NONO_v0.4.3` / `AgentSessionRecord` / Liam design §4: C3 is met by derivation (route = `/svc/<service_id>`).

### Service URL validation (LOCKED, amendment §2 item 1, §5.5)
- **D-03** Read `NONO_SERVICE_HOMETOWN_URL` and `NONO_SERVICE_OLIVE_URL`. Each must be exactly `http://127.0.0.1:<port>/svc/hometown` and `http://127.0.0.1:<port>/svc/olive` respectively: `http` scheme, IPv4 literal `127.0.0.1` (not `localhost`, not `[::1]`, not a host name), no userinfo, no query, no fragment, no trailing segments beyond the route.
- **D-04** `<port>` must equal the agent-session record's `proxy_port`.
- **D-05** Exit 11 reasons, one reason line, before any network request and with no run record: `env:service_url_missing` (absent or empty), `env:service_url_not_loopback` (scheme/host/userinfo/query/fragment wrong), `env:service_url_port` (port ≠ `proxy_port`), `env:service_url_route` (route not `/svc/hometown` / `/svc/olive` for that variable).
- **D-06** `NONO_SERVICE_GATEWAY_URL` is ignored (never read). Liam never calls the gateway (REQ-LIAM-11).
- **D-07** Validation is a pure function taking inputs as arguments (pattern of `config::validated_proxy` / `validate_startup`) so it is unit-testable without env or filesystem.

### Config (LOCKED, amendment §2 item 2, §5.6)
- **D-08** Remove `[hometown].base_url` and `[olive].base_url` from `liam.toml` and from `src/config.rs`. Keep timeouts and catalog fields. Liam request paths are appended to the validated service URL.

### Client (LOCKED, amendment §2 item 3)
- **D-09** The single client constructor keeps `ClientBuilder::no_proxy()` and `.dns_resolver(DenyAllResolver)` and **drops** `.proxy(Proxy::all(..))`. No second client. `resolver_calls()` counter stays.
- **D-10** Forward-proxy env vars `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY` are no longer read for routing. Retire `env:proxy_not_loopback` and `env:no_proxy_nonempty` and their checks. (Open item O-A: whether to refuse when they are set; NOT in scope unless the user decides at the gate; default = ignore them.)

### Tests (LOCKED, amendment §7)
- **D-11** TC-NET-03 static check revised: additionally forbid `Proxy::` in Liam's own source (outside feature-gated stubs); constructor must call `no_proxy()` and `dns_resolver(..)` and no `proxy(..)`.
- **D-12** TC-NET-05 revised: per variable, cases `http://localhost:p/r`, `http://[::1]:p/r`, `http://svc.lab:p/r`, `https://127.0.0.1:p/r`, `http://u:pw@127.0.0.1:p/r`, `http://127.0.0.1:p/r?x=1`, port ≠ `proxy_port`, wrong route, unset → exit 11 with the D-05 reason; no listener connection; no run record.
- **D-13** TC-NET-09 new: stub run; the capturing listener on `127.0.0.1:<proxy_port>` serves both routes; every request arrives as plain HTTP under `/svc/hometown` or `/svc/olive`; no CONNECT; no `Authorization` header.
- **D-14** TC-NET-06 (resolver count 0) and TC-NET-07 (WinINET trap ignored) keep passing; TC-KEY-01 (no `Authorization`) keeps passing.

### Stubs (feature `stubs`)
- **D-15** `src/stubs.rs` capture proxy becomes a capturing reverse-proxy/listener that serves `/svc/hometown/...` and `/svc/olive/...` by routing to the in-process Hometown/Olive stubs (or serving them directly), records method/path/headers for assertions, and records any CONNECT attempt. Stub record pair (`scripts/make-stub-records.ps1`, stub agent record) keeps `proxy_port` equal to the listener port. `LIAM_STUBS` / `LIAM_STUB_PID` behaviour otherwise unchanged; stubs stay excluded from release.

### Docs / change control
- **D-16** Fold amended text into README (D14 description, exit codes table, v0.4.1 conformance notes A5 superseded) and update the amendment Status line to "Ratified … implemented in Phase 02.1" only after tests pass. The README "Announced nono deviation" note is updated to say Liam implements it.
- **D-17** `profiles/liam.nono.toml`: if it declares network/proxy expectations tied to CONNECT, record the needed profile change for the nono owner; do NOT edit profile semantics beyond what the amendment states (contract-only nono coupling). Planner decides after reading the file.

### Claude's Discretion
- URL parsing approach (manual strict parse vs `reqwest::Url`/`url` crate already vendored) as long as no name resolution can occur and the exact-form rules hold. Prefer an already-vendored crate; no new dependencies (offline vendored build).
- Plan split and wave layout.
- Where the validator lives (`src/config.rs` next to the retired `validated_proxy`, or a new small module).

</decisions>
